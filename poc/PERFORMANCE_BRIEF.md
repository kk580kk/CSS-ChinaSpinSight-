## 三、发现的关键问题 🚨

### 1. POC 代码有模型维度假定错误
`poc/weapp-yolo/utils/inference.js` 第 14 行：
```javascript
this.inputShape = [1, 3, 320, 320]; // 量化模型使用 320x320 ✗
```
实际模型输入为 `[1, 3, 640, 640]`。这个 bug 会导致小程序一运行就崩溃。
**修法**: 改成 640x640，或重新导出 320x320 的模型。

### 2. 合成图像测试的局限
目前所有测试基于合成图像。真实场景中乒乓球小、速度快、背景复杂，COCO 预训练模型未必能稳定检出。需要：
- 用真实乒乓球视频验证
- 或训练乒乓球专用检测模型

## 四、移动端性能估算依据

| 因子 | 倍率 | 说明 |
|------|------|------|
| WASM vs 原生 | 2-3x | WebAssembly 解释执行开销 |
| M4 vs 手机旗舰 | 1.5-2x | M4 单核性能≈A17 Pro |
| M4 vs 中端机 | 3-5x | M4 大幅领先 |
| 优化潜力 | 0.5x | SIMD, 320x320 模型, WebGL 后端 |

**估算公式**: `移动端延迟 = 32ms × (WASM倍率) × (CPU倍率)`
